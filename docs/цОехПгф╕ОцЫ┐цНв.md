# 主线一二的接入与替换

系统把算法封装在两个Python对象里。它们构造时接收Settings，内部可以调用队友的包、加载权重，或请求单独的推理服务。项目没有要求队友使用本示例的模型架构或特征维度。

## 采集上传协议 v1

POST `/api/tasks`，使用multipart/form-data：

- metadata：JSON字符串，必填。
- eeg：可选EDF文件。
- face：可选PNG/JPG图片。
- audio：可选WAV/OGG/FLAC文件。

metadata示例：

```json
{
  "subject_id": "demo_01",
  "collection_id": "session001_epoch001",
  "collected_at": "2026-10-06T10:00:00+08:00",
  "text": "今天的文本描述",
  "scenario": "中风险演示"
}
```

采集编号由客户端生成，重传时使用相同编号；同一人的相同编号表示同一不可变采集。即使上传内容改变，系统也返回原任务；需要修正内容时请使用新编号。服务器统一将时间转成UTC保存，页面以北京时间显示。当前一个包只有采集时间，不声称拥有样本级时间同步。

POST `/api/demo` 使用同样的JSON字段，服务器会复制公开样例并标记source=demo。

GET `/api/tasks/{id}` 查看完整状态、特征和结果；GET `/api/records` 按subject_id/start/end筛选；POST `/api/tasks/{id}/retry` 重试失败任务；GET `/api/export` 按同样条件导出CSV。start包含边界，end不包含边界。

`app/adapters/features.py` 的DemoFeatureExtractor实现：

```python

```

Sample.files是模态名到服务端文件路径的映射，Sample.text是文本。缺少的模态不会出现在files中。队友可以独立处理每种模态，保留自己的特征命名、单位、采样率、时间索引和质量标志。

在config.toml修改：

```toml
[plugins]

predictor = "app.adapters.predictor:MockPredictor"
```

返回值的modalities是字典。每项包含有限数值组成的values、可选names和metadata。对于时序张量，可以将值展平，并在metadata保存shape、时间戳、mask和layout；数据量大时升级契约为文件引用，增加schema_version。不要把高维原始流塞进数据库JSON。

本版只实现原始文件上传。若队友决定在客户端完成特征提取，后续增加 `/api/features` 并复用FeatureBundle校验与预测模块；不要把特征文件伪装成EDF。双方先商定计算位置，再实现该入口。

## 主线二替换点

`app/adapters/predictor.py` 的MockPredictor实现：

```python
def predict(self, features: FeatureBundle, sample: Sample,
            history: list[dict], scenario: str | None) -> Prediction:
    ...
```

新增真实模型适配器，构造时加载一次模型，预测时完成：

1. 检查extractor_version与训练时一致。
2. 按队友规定的顺序、维度、标准化参数、时间窗口组装Tensor。
3. 调用模型的eval推理路径；如使用PyTorch，设置eval并使用inference_mode。
4. 返回score、model_version、is_simulated、explanation。

score必须为0至100的有限数值。模型还未验证时不要把is_simulated=False当作“已证明医学有效”，该字段只区分模拟输出和真实模型计算。风险映射配置由团队确定，不应把原模型分类标签直接当成心理风险。

history目前只包含同一subject_id、严格早于本次collected_at的成功结果，最多1000条。它是明确的数据入口，不会自动让模型具备跨数周学习能力。真实模型使用哪些字段、是否排除模拟历史、怎样处理缺失和模型版本变化，应由主线二适配器明确处理。

然后仅修改predictor配置路径并重启后端。真实模型接入后，可隐藏页面的模拟场景选择器。旧模拟记录应保留标记或使用独立运行目录，防止混入研究分析。

## 团队交付检查

- 提供一份可运行的真实样例和预期输出。
- 明确原始文件格式、时间单位、通道顺序、采样率、缺失模态策略。
- 提供特征处理代码、配置和版本；正式模型必须使用训练时同一处理流程。
- 提供模型结构代码、权重、归一化参数、依赖版本、推理函数。
- 说明历史序列组织、个体状态维护与0—100分数的含义。
- 用同一个样例比较独立推理与HTTP任务结果。

`tests/test_api.py::test_plugin_replacement_and_history` 演示了配置替换另一个预测器，验证任意特征长度及历史筛选，不要求修改路由、数据库或页面。
